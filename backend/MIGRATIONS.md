# Database Migrations

Alembic-based database migrations for SQLModel. Migrations auto-apply at startup.

## Quick Start

### Generate Migration
```bash
cd backend/
uv run alembic revision --autogenerate -m "Description"
```

### Apply Migration
```bash
# Manual
uv run alembic upgrade head

# Or just start the app (auto-applies)
uv run uvicorn main:app --reload
```

### View History
```bash
uv run alembic current      # Current version
uv run alembic history      # All migrations
```

### Rollback
```bash
uv run alembic downgrade -1    # Back one version
uv run alembic downgrade base  # Rollback all
```

## How It Works

1. **Database config** (`components/shared/database.py`): `DatabaseConfig` abstraction with `SQLiteConfig` and `PostgreSQLConfig`
2. **Settings** (`config.py`): `sqlite_db_path` configurable via env var `SQLITE_DB_PATH`
3. **Alembic env** (`alembic/env.py`): Loads DB URL from config, imports all models
4. **Startup** (`main.py`): `database.run_migrations()` auto-applies migrations

## Adding New Models

**1. Create the model:**
```python
from sqlmodel import SQLModel, Field
from uuid import UUID, uuid4

class MyModel(SQLModel, table=True):
    __tablename__ = "my_table"
    id: UUID = Field(default_factory=uuid4, primary_key=True, index=True)
    name: str = Field(..., unique=True)
```

**2. Import in `alembic/env.py`:**
```python
from components.my_component.entities import MyModel  # noqa: F401
```

**3. Generate migration:**
```bash
uv run alembic revision --autogenerate -m "Add MyModel table"
```

**4. Review & apply:**
```bash
# Check the generated file in alembic/versions/
uv run alembic upgrade head
```

## Modifying Models

**1. Update the model**
**2. Generate migration:**
```bash
uv run alembic revision --autogenerate -m "Add field to Model"
```

**3. Review carefully** - especially:
- Non-nullable fields (handle existing data)
- Foreign keys
- Column renames (autogenerate may misdetect as drop+add)

**4. Edit migration if needed:**
```python
def upgrade() -> None:
    # Add nullable first
    op.add_column('table', sa.Column('field', sa.String(), nullable=True))
    # Populate existing rows
    op.execute("UPDATE table SET field = 'default'")
    # Make non-nullable if needed
    op.alter_column('table', 'field', nullable=False)
```

## Configuration

### SQLite (default)
```python
from components.shared.database import Database, SQLiteConfig
db_config = SQLiteConfig(Path("~/.syai-server/app.db").expanduser())
database = Database(db_config)
```

### PostgreSQL
```python
from components.shared.database import Database, PostgreSQLConfig
db_config = PostgreSQLConfig(host="localhost", port=5432, database="syftai", user="postgres", password="pass")
database = Database(db_config)
```

### Environment Variables
```bash
SQLITE_DB_PATH=/path/to/db.db
RESET_DB=false  # Drop all tables on startup
```

## Troubleshooting

### No changes detected
- Check model imported in `alembic/env.py`
- Verify `table=True` on model
- Run from `backend/` directory

### Database locked (SQLite)
- Use single worker: `--workers 1`
- Switch to PostgreSQL for production

### Migration fails at startup
- Fallback to `create_all()` happens automatically
- Check logs for errors
- Verify `alembic.ini` exists

### Out of sync database
```bash
uv run alembic stamp head  # Mark as current
# Or start fresh (dev only)
rm ~/.syai-server/app.db && uv run alembic upgrade head
```

## Best Practices

- Always review autogenerated migrations
- Test on dev database first
- Handle existing data for schema changes
- Never edit applied migrations (create new ones)
- Commit migrations with model changes
- Backup before production migrations

## Production Deployment

```bash
# Backup
cp ~/.syai-server/app.db ~/.syai-server/app.db.backup

# Apply migrations
cd backend/
uv run alembic upgrade head

# Start app (or let it auto-migrate)
uv run uvicorn main:app --host 0.0.0.0 --port 8080
```
