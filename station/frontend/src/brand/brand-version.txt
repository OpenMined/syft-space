How the brand reaches components
--------------------------------
Page theme:  [data-theme="dark"] on <html> (set in index.html pre-paint +
             src/composables/useTheme.ts). data-section overrides
             (always-light / always-dark / invert) are supported.
Adapter:     shadcn's semantic tokens (--background, --primary, …) are redefined
             in src/style.css over the OMDS tokens — surfaces/text/border over
             the *semantic* layer (so data-section flows through every shadcn
             utility), accents over the *palette* ramps.

Accent palette — teal brand + semantic action colors (all OMDS-canonical)
-------------------------------------------------------------------------
  --primary    teal-600  #388ca8   BRAND primary: neutral CTAs, accents, focus,
                                    ring, sidebar (hover -> teal-700 #2a697e)
  --success    lime-700  #429541   POSITIVE: the Approve button + healthy/approved
                                    status (button variant "success"; hover lime-800)
  --destructive red-600  #b73d56   NEGATIVE: Reject + delete + error (hover red-700)
  --warning    gold-600  #f5a22e   caution / pending
  --secondary  neutral             quiet grey chip (surface-foreground-low) — used
                                    for info badges, NOT a second brand hue
  --info       blue-500  #6976ae   optional accent (bg-info / text-info)
  charts       teal-500 · green-500 · lime-600 · gold-500 · violet-500
  neutrals     OMDS grayscale (warm violet-black), via the semantic surface/text layer

  Semantic-colour model: teal = brand, green = yes/positive, red = no/negative.
  Approve(create)=green, Reject(create)=red; Approve(delete)=red (destructive),
  Decline(delete)=neutral outline (declining a deletion is the safe path).
